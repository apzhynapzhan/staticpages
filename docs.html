building from source

clone the main repo and run the build script:

git clone https://codeberg.org/StaticLinux/rootfs
cd rootfs
sh build.sh

the build script downloads sources, compiles the kernel and busybox, and produces a bootable squashfs image.

booting in qemu

qemu-system-x86_64 \
  -kernel vmlinuz \
  -initrd initramfs.img \
  -drive file=staticlinux.squashfs,format=raw \
  -m 512M \
  -nographic \
  -append "console=ttyS0"

exit qemu with Ctrl+A then X.

the initramfs (initpromefs) extracts the squashfs rootfs into memory and hands off to prometheus.

installing packages

sync the ports tree first:

ace fetch

then install by category/name:

ace install shells/dash
ace install vcs/git

remove a package:

ace remove shells/dash

list installed packages:

ace query

inspect a specific package:

ace query dash

writing a port

each port is a single .scheme file under its category in static-ports:

static-ports/
  shells/
    dash/
      dash.scheme
  vcs/
    git/
      git.scheme

port format:

(package
  (name "dash")
  (version "0.5.12")
  (category "shells")
  (description "minimal POSIX shell")
  (source "http://gondor.apana.org.au/~herbert/dash/files/dash-0.5.12.tar.gz")
  (sha256 "...")
  (binary "dash-0.5.12/src/dash")
  (install "/usr/bin/dash")
  (build
    (env "CC" "x86_64-linux-musl-gcc")
    (run "./configure" "--host=x86_64-linux-musl" "--enable-static")
    (make)))

ace downloads the source, verifies the sha256, extracts it, runs the build instructions, strips the binary, and installs it.

to test a port locally:

ace install shells/dash

prometheus

PID1, written in Rust. boots in two stages.

stage0: mounts filesystems, sets hostname from /etc/hostname, seeds rng, brings up loopback.

stage1: spawns getty on tty1, tty2, and ttyS0, then opens a unix socket listener at /run/prometheus.sock for promectl.

after stage1, runs /var/lib/prometheus/autoexec.sh if it exists.

promectl

control CLI for prometheus. talks to /run/prometheus.sock over a line-based text protocol.

promectl reboot
promectl poweroff
promectl halt

client writes the command, shuts down the write half of the socket, then reads the response. skip the shutdown and you'll deadlock waiting on each other.

superpose (in progress, not shipped)

service supervisor for prometheus. not implemented yet - this page exists so the sidebar link isn't dead.

planned layout, one file per service:

/etc/superpose/services/<svc>.scheme

neostrap

bootstraps a fully self-hosted clang+musl toolchain from a 400KB statically linked tcc binary. fork of bootstrap-from-tcc with nix ripped out - pure sh/make, no nix anywhere in the chain.

used as the reference bootstrap for Static Linux's musl/clang toolchain.

stage graph

stage1 is hand-written C run directly against the tcc seed (no libc, no stdlib) inside an unshare+chroot sandbox. it builds enough of musl and busybox from scratch to get a working shell, then rebuilds tcc itself three times against its own output.

0-tcc-seed        pack the supplied tcc-seed binary
1-stage1          protomusl + protobusybox + self-hosted tcc

everything past stage1 is plain recipe scripts (recipes/*.sh), each one a chroot'd shell script with declared package deps. stage 2a climbs from tcc up to an intermediate clang using GNU toolchains as scaffolding:

2a0  static gnumake        2a5  gcc10 (musl-targeting)
2a1  static binutils       2a6  linux headers
2a2  gcc4 (C only)          2a7  cmake
2a3  intermediate musl      2a8  python
2a4  gcc4 (C++)             2a9  intermediate clang (LLVM 17, 2-stage)

stage 2b rebuilds the final, self-hosted set using only the intermediate clang from 2a9 - no GNU toolchain left in the output:

2b0  musl (final)
2b1  clang (final, self-hosted, linked against 2b0)
2b2  busybox (built with 2b1)
2b3  gnumake (built with 2b1)

everything is content-addressed: each pkgs/<stage>.pkg is a deterministic tar+zstd of store/<stage>, with SOURCE_DATE_EPOCH pinned and build paths scrubbed.

usage

simple, non-incremental path - supply tcc-seed, then exec straight through everything:

./build.sh

incremental, for debugging a specific stage:

make all-pkgs       # build every stage
make pkgs/2b1-clang.pkg   # build up to a specific stage
make all-tests      # run the _N.test.pkg sanity checks

reproducibility checks against a committed checksum manifest:

make verify-pkgs-checksums       # check existing pkgs/ against verify.pkgs.sha256
make verify-all-pkgs-checksums   # build everything, then check
make update-pkgs-checksums       # regenerate the manifest

build isolation knobs, set as env vars or make args: USE_CCACHE=1 caches compiler output per-stage, USE_DISORDERFS=1 shuffles directory entry order during builds to catch order-dependence bugs, SAVE_MISMATCHING_BUILD_TREES=1 stashes a full build tree to trees/ whenever a checksum doesn't match.

requirements

a statically linked tcc binary at ./tcc-seed, linux x86_64, ~8GB free for the build tmpfs, and several hours - the full chain takes 4-8 hours depending on hardware.

fetching sources

recipe scripts declare their downloads inline with magic comments:

#> FETCH <sha256>
#>  FROM <url>
#>    AS <local filename>

download.sh scans for these (plus the old nix-derivation form, for upstream compat), fetches into downloads/, and verifies the hash before copying into the build's DESTDIR.

ace

package manager written in C. fully static, musl only. no runtime deps.

ace fetch            # sync ports tree
ace install <pkg>   # build and install
ace remove <pkg>    # uninstall
ace query [pkg]     # list or inspect

ports use a simple scheme-based DSL. the build system supports env, run, and make instructions.

ports are fetched from ports.staticlinux.org. the ports tree mirrors the static-ports repo on every push.

recount

optional package updater written in C. compares installed versions against the ports tree and rebuilds outdated packages via ace.

recount <pkg>    # upgrade a single package
recount @matters # upgrade all packages

to ignore a package from upgrades, add it to /var/lib/recount/ignore.scheme:

(ignore
  "zig-bin"
  "kernel")

run ace fetch before recount to sync the latest port definitions.
